# Научный поиск по анатомии

Соблюдай AGENTS.md. Этот skill получает и проверяет литературу; [anatomy-validator](../anatomy-validator/SKILL.md) отвечает за применение доказательств к анатомическим полям. Не загружай оба целиком без необходимости.

## Порядок работы

1. Сформулируй одно утверждение: структура, сторона, поле, человек/возраст/вариант. Найди проверенные PMID/DOI и нужный раздел ANATOMY_SOURCES_AUDIT.md; переиспользуй результаты, не повторяй полный аудит.
2. Сверь термин и код с официальной [FIPAT](https://ifaa.net/committees/anatomical-terminology-fipat/fipat-ifaa-terminologies/) и scripts/ta98.py. В проекте TA98; TA2 и свободный перевод не подменяют код или официальный эквивалент. Номенклатура не доказывает топографию.
3. Для PubMed используй официальный ESearch, затем пакетный EFetch нужных PMID. Начни с 3–5 результатов, английского термина/синонимов и [Title/Abstract]; изучи querytranslation и предупреждения. При пустом ответе уточни запрос: отсутствие находки не доказывает отсутствие структуры.
4. Сопоставь PMID, DOI, полное название, авторов и даты из EFetch с PubMed/издателем. Различай электронную и печатную даты; отсутствующий DOI/год оставляй неизвестным. Проверь PublicationType и CommentsCorrections, затем доступные уведомления издателя об исправлении/отзыве. Пустой список уведомлений не гарантирует их отсутствия.
5. Открой относящийся к утверждению текст. Для [Bookshelf](https://www.ncbi.nlm.nih.gov/books/) фиксируй NBK-ID, авторов главы, обновление, раздел/рисунок и доступ; PMID/DOI — только реально присвоенные. Поиск, аннотация и полный текст — разные уровни доступа. Не обходи ограничения доступа; площадка не гарантирует качество и общую лицензию.
6. Для нового или спорного факта ищи минимум две независимые адресные опоры, если доступны: первичное морфологическое исследование и независимую работу/академический атлас. Обзор и его исходная выборка не дают двух независимых наблюдений. Сверяй выборку, метод, сторону и определения; разногласия и нехватку данных сохраняй явно.
7. Раздели выводы: **термин/анатомический факт**; **относительная топография**; **геометрия конкретного образца**. Текст, рисунок и средние размеры не задают координаты пина, контур или масштаб GLB. Геометрическую приёмку передавай mesh-auditor/Blender с идентифицированным исходником.

## Воспроизводимый API

Из корня проекта, доступным Python 3; дополнительных пакетов нет:

```text
python .agents/skills/medical-literature-research/scripts/pubmed.py --query "jugular foramen[Title/Abstract] AND anatomy[Title/Abstract]" --limit 5 --out research/pubmed-jugular-search.json
python .agents/skills/medical-literature-research/scripts/pubmed.py --ids 41404679,36635090 --out research/pubmed-jugular-records.json
```

- Сначала проверь сохранённый JSON. Скрипт не перезаписывает файл без --overwrite; stdout содержит только сводку. Не читай весь JSON, если нужны две записи.
- Только https://eutils.ncbi.nlm.nih.gov/entrez/eutils/; ESearch JSON и EFetch XML. Сохраняются метаданные и предупреждения, не полные тексты/аннотации. Релевантность оценивает исследователь, не скрипт.
- Последовательные запросы с паузой ≥0,4 с; не запускай копии параллельно: лимит NCBI общий для IP. До двух повторов при 429/5xx, затем отчёт о сбое. API-тест пройден только при реальном ответе API.
- NCBI_EMAIL и NCBI_API_KEY можно передать через окружение; не выдумывай контакт, не печатай ключ. Для малой выборки ключ необязателен. Для регулярного сервиса используй настоящий контакт и процедуру регистрации tool/email NCBI; письма без разрешения не отправляй.
- [Правила NCBI](https://www.ncbi.nlm.nih.gov/sites/books/NBK25497/), [параметры API](https://www.ncbi.nlm.nih.gov/sites/books/NBK25499/), [Disclaimer/Copyright](https://www.ncbi.nlm.nih.gov/About/disclaimer.html). Доступ к публикации не разрешает автоматически копировать иллюстрации/модели.

## Результат

Краткая таблица: утверждение/ID → проверенные метаданные → точный локатор/доступ → независимость → вывод/уверенность → предел доказательства. Не выдумывай библиографию, координаты или недостающие сведения. Обнови журнал и существующие ID проблем по правилам проекта; научная проверка не закрывает геометрический блокер. Сам поиск не разрешает менять данные приложения.
