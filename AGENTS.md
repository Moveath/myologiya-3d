# AGENTS.md — как устроен проект и как его менять

Сначала прочитай README.md (цель, правила точности, бэклог). Здесь — техника.

## Правила (обязательно)

- Весь текст интерфейса и карточек — на русском, латынь — по TA98. Не выдумывать анатомические факты: любое новое утверждение сверить минимум с двумя независимыми источниками; если источники расходятся — написать об этом в карточке (поле `note` у мышцы или в описании точки).
- Точки на костях: на каждой кости ровно официальный список TA98. Таблица терминов — `scripts/ta98.py` (код → латынь, русский, флаги); какие коды обязаны быть на какой кости — словарь `BONE` там же. `make_pins*.py` падают с ошибкой, если на кости не хватает или есть лишний термин. После правок запускать `python3 verify/verify_ta98.py` (ожидается ровно 3 известных расхождения, они описаны в самом скрипте).
- `site/pins.js` и `site/pins-leg.js` руками не править — они генерируются (см. ниже). Тексты точек правятся в `scripts/make_pins.py` / `scripts/make_pins_leg.py`.
- Ничего не брать из платных атласов/приложений. 3D-модели — только из открытых источников с совместимой лицензией (BodyParts3D — CC BY-SA 2.1 JP: указывать авторство, производные — под той же лицензией).
- Проверять вёрстку на ширине 390 px (телефон) и 1280 px, в светлой и тёмной теме.

## Сайт (`site/`)

- `index.html` — вся страница в одном файле (CSS + разметка + JS-модуль). Это **фрагмент** без `<!doctype>`/`<html>`: так требует хост Claude Artifacts. Для обычного хостинга и локального запуска: `python3 scripts/make_local.py site/index.html site/local.html`.
- three.js 0.170.0 подключается через importmap с cdn.jsdelivr.net (OrbitControls, GLTFLoader, MeshoptDecoder).
- Модели: `arm-glb.txt`, `leg-glb.txt` — GLB (сжатие meshopt) в base64; если не загрузились — `arm-q-glb.txt` / `leg-q-glb.txt` (без `-cc`). Base64 — потому что хост артефактов не отдаёт `.glb`; на обычном хостинге можно перейти на `.glb` (поменять `fetchModel`).
- Имена узлов в GLB: `m|<мышца>|<часть>`, `b|<кость>`, `o|<связка/перепонка>`, `c|<id>` (кости-контекст). gltfpack кладёт имена на родительские узлы — при обходе сцены идти вверх по родителям (так сделано в `register`).
- Система координат: BodyParts3D (мм, Z вверх, −Y вперёд) → three.js: `x = x`, `y = z`, `z = −y`, в метрах. Правая сторона тела = −x; для правой конечности +x — медиально, +z — вперёд.
- Основное в `index.html`: `SECTIONS` (разделы и подразделы), `GLOSS` (словарик), `fetchModel/register/loadSection`, `visState/applyVisibility/paint` (видимость: 0 скрыто, 1 бледно, 2 видно), `frame/frameBox/framePart/frameSub`, точки: `currentPins/buildPins/positionPins/computeOcclusion/flyToPin/activatePin`, карточка: `renderSheet`, `bonePinSect` (список образований TA98 по группам), `pinMeta`, навигация: `select`, `goTo`, `setSub`, `enterSection`, `showHome`, список: `renderList`, тест: `quizPool/nextQuestion/renderQuiz`, стартовый экран: `renderHome/renderFigure/layoutFigure`.
- Для отладки на странице есть `window.__atlas = { enterSection, setSub, select, goTo, activatePin, showHome, state }` и `window.__ready`.

### Форматы данных

- `window.ATLAS.groups`: `{id, title, sec, region}`; `boneGroups`: `{id, title, sec}`.
- Мышца (`ATLAS.muscles[id]`): `lat, ru, g` (группа), `d` (слой 1–3), `v` (ракурс), `L` (подпись слоя), `o, i, a, n, s` (начало, прикрепление, функция, иннервация, кровоснабжение), `note`, `noModel`, `parts: {ключ: {ru, lat, o, i, a, n, x}}` — ключ части совпадает с `<часть>` в имени узла модели.
- Кость (`ATLAS.bones[id]`): `ru, lat, g, sub` (подраздел), `x` (описание).
- Точка (`ATLAS.pins[]`): `b` (кость), `id`, `t` (`ta` — термин TA98, `att` — место прикрепления без термина, `soft` — точка на связке/перепонке), `c` (код TA98), `ru`, `lat`, `x` (описание), `p` (координаты), `n` (нормаль), `m` (`[[мышца, 'o'|'i', часть?]]`), `g` (часть кости, например «Подвздошная кость (os ilium)»), `inc: 1` (непостоянное), `sh` (список костей, если термин общий — борозда запястья), `part: 1` (сама кость-часть, например копчик; в счёт не входит).
- Для маркеров головы дополнительно: `loc` (`surface`, `projection`, `internal`, `variant`), `modelNote` (что именно показывает маркер и чего не подтверждает модель). В исходных JSON тип называется `localization`; `evidence` хранит метод выбора и сведения о проверке, `refs` — источники с отдельным `locator`. Не терять эти различия при генерации и отображении.

## Конвейер сборки

Зависимости: Python 3 (`pip install numpy trimesh fast-simplification pillow scipy playwright`, затем `python3 -m playwright install chromium`), Node.js (`cd tools && npm install` — three@0.170.0 и gltfpack).

1. STL-файлы BodyParts3D (в репозиторий не входят, ~270 МБ):
   ```
   python3 scripts/fetch_stl.py manifest stl_dl
   python3 scripts/fetch_stl.py manifest_leg stl_leg
   python3 scripts/fetch_stl.py body stl_body
   ```
   Состав моделей — `scripts/manifest.py` (рука) и `scripts/manifest_leg.py` (нога; названия → id через `bp/all_named.tsv`).
2. Модели (кости — без дополнительного упрощения исходных STL; исходники BodyParts3D 3.0 уже имеют ограниченную детализацию; мышцы упрощаются):
   ```
   BONE_RATIO=1.0 BONE_MAX=20000 python3 scripts/build_glb.py scripts stl_dl build/arm_hi.glb build/meta.json manifest
   BONE_RATIO=1.0 BONE_MAX=20000 python3 scripts/build_glb.py scripts stl_leg build_leg/leg_hi.glb build_leg/meta.json manifest_leg
   node tools/node_modules/gltfpack/cli.js -i build/arm_hi.glb -o build/arm.glb -cc -kn -km
   node tools/node_modules/gltfpack/cli.js -i build/arm_hi.glb -o build/arm_q.glb -kn -km
   (то же для build_leg/leg_hi.glb → leg.glb, leg_q.glb)
   python3 -c "import base64,sys; open(sys.argv[2],'w').write(base64.b64encode(open(sys.argv[1],'rb').read()).decode())" build/arm.glb site/arm-glb.txt
   (то же для arm_q → arm-q-glb.txt, leg → leg-glb.txt, leg_q → leg-q-glb.txt)
   ```
3. Координаты точек (нужны только если менялись модели или добавляются кости). Инструмент — `build/pintool.html` (рука) и `build_leg/pintool.html` (нога): ортографические виды кости с сеткой u/v, `pick(кость, вид, u, v, zoomBox)` бросает луч на поверхность. Расчёт: `landmarks.js` (старый набор ориентиров, используется как опорные точки) и `landmarks_ta.js` (все термины TA98 + места прикрепления).
   ```
   NM=$PWD/tools/node_modules python3 scripts/driver.py build "pintool.html?f=arm_hi.glb" qarm 8773 &
   python3 scripts/export_positions.py qarm pins/ta.json pins/old_hi.json
   NM=$PWD/tools/node_modules python3 scripts/driver.py build_leg "pintool.html?f=leg_hi.glb" qleg 8772 &
   python3 scripts/export_positions.py qleg pins_leg/ta.json pins_leg/old_hi.json
   ```
   Визуальная проверка (картинка появится в `qarm/v1.png`): `python3 scripts/q.py qarm v1 "showTA('scapula','post')"`. Виды: `ant, post, lat, med, sup, inf` или свой `{d:[x,y,z], up:[x,y,z]}`. Остановить драйвер: `touch qarm/_STOP`. Позиции в `landmarks_ta.js` подобраны под эти модели — после пересборки моделей обязательно пересмотреть снимки каждой кости.
4. Точки → сайт (с проверкой полноты списков TA98 по каждой кости):
   ```
   python3 scripts/make_pins.py pins/ta.json pins/old_hi.json site/pins.js
   python3 scripts/make_pins_leg.py pins_leg/ta.json pins_leg/old_hi.json site/pins-leg.js
   python3 verify/verify_ta98.py
   ```
5. Фигура стартового экрана (менять редко):
   ```
   python3 scripts/build_body.py skeleton_parts.json stl_body body/body.glb
   NM=$PWD/tools/node_modules python3 scripts/render_body.py body body/out 560 1240
   ONLY=mask NM=$PWD/tools/node_modules python3 scripts/render_body.py body body/out 1120 2480
   python3 scripts/compose_body.py body/out site
   ```
6. Проверка страницы в headless Chromium (скриншоты `shots/x_N.png`, ошибки консоли печатаются):
   ```
   python3 scripts/make_local.py site/index.html site/local.html
   NM=$PWD/tools/node_modules python3 scripts/shot.py site local.html shots/x 1280 860 "window.__atlas.enterSection('leg').then(()=>1)" "window.__atlas.goTo('hip_bone'); 1"
   ```

`scripts/parts_patch.py` — разовая миграция `data.js` (части мышц), повторно не запускать.

## Как добавить новый раздел (например, мочеполовую систему)

1. Манифест структур (как `manifest_leg.py`) + `fetch_stl.py` + `build_glb.py` → `site/<раздел>-glb.txt`.
2. Данные карточек — новый `site/data-<раздел>.js` (группы с `sec: '<раздел>'`, структуры, тексты с проверкой по 2+ источникам), подключить в `index.html`.
3. Запись в `SECTIONS` (id, ru, hint, `ready: true`, `file`, `subs`, `tries`) и, если нужно, новые группы в `register`/`visState`.
4. Образования по TA98 — дописать коды и русские термины в `scripts/ta98.py`, требуемые списки — в `BONE`, позиции — через pintool, описания — в новом `make_pins_<раздел>.py`.
5. Обновить «Как пользоваться» (диалог `#about`) и счётчики, проверить на телефоне и в тёмной теме.

## Добавленный раздел головы

- `scripts/manifest_head.py` — исходные STL обеих сторон: 22 кости, 43 моделируемых экземпляра мышц, сухожильный шлем и зубы-контекст.
- `scripts/head_muscles.py` — 27 шаблонов / 52 карточки и ссылки по полям. Генератор `scripts/make_head_data.py` создаёт `site/data-head.js`; этот файл не редактировать вручную.
- `scripts/head_terms.py` расширяет `T` и `BONE` в `ta98.py`. Три различия редакций черепа проверяются по печатному TA98 отдельно, до проверки трёх известных расхождений ноги. Не убирать проверку исходных значений IFAA.
- `scripts/make_pins_head.py` создаёт `site/pins-head.js` и `verify/head-coverage.json`; генерируемый файл сайта вручную не править. `scripts/head_localization.py` объединяет исходные `pins_head/ta.json`, уточнения `pins_head/{face,cranial,temporal}-extra.json` и `pins_head/face-completion.json` по паре «кость, код TA98». Исходные экранные выборки — `build_head/landmarks_ta.js`, новые и исправленные — `build_head/landmarks_{face,cranial,temporal}_extra.js`. Шесть записей `face-completion.json` подтверждают существующий рельеф с обеих сторон: верхнечелюстной отросток нижней носовой раковины, слёзную борозду и раковинный гребень нёбной кости; геометрия BodyParts3D при этом не изменялась.
- Все 521 записи для 22 костей имеют маркеры: **325 `surface`, 182 `projection`, 14 `variant`**. `surface` обозначает участок видимого рельефа, поверхности или края отверстия; `projection` — анатомически обоснованную ожидаемую область, когда конкретный мелкий рельеф или просвет на сетке не подтверждён; `variant` — типичное место варианта без утверждения о его наличии у данного человека. Формат допускает `internal` для отдельно обоснованной внутрикостной позиции, но таких маркеров сейчас нет. Полный охват координатами не означает полную реконструкцию микрогеометрии.
- Не генерировать фиктивные позиции из ограничивающих параллелепипедов и не выдавать попадание луча в поверхность за проверку анатомического образования. Для каждой новой или изменённой точки сохранять метод выбора, вид, ограничения геометрии и источники. Парные кости проверять по обеим сеткам; отражение координат не заменяет отдельного осмотра. При выборе медиальной стороны нижней челюсти не попадать лучом в противоположную ветвь.
- Краткая топография всех 349 разных терминов и ссылки с локаторами находятся в `scripts/head_{face,cranial,temporal}_evidence.py`. В каждой записи `DESCRIPTIONS` нужны два независимых анатомических источника; номенклатурные справочники отдельно подтверждают названия.
- `taParen` отражает скобки электронной номенклатуры и не используется как автоматическое доказательство непостоянства.
- `scripts/export_head_evidence.py` обновляет `research/head-evidence.json`. В реестре разделены анатомические и номенклатурные источники; ограничения маркеров сохранены отдельно. Кэш книг и сторонних статей не публикуется.
- `research/head-model-review.json` хранит историю сравнения открытых моделей. `research/skull-detailed-sources.json` — подробный поиск дополнительных источников, лицензии и ограничения. BodyParts3D остаётся основной моделью с проверенными маркерами; дополнительные Z-Anatomy, Halle микро-КТ и OpenEar имеют собственные координаты и независимый просмотр. `research/cache/` в публикацию не включать. Повторные проверки сохранены в `research/{face-completion-review,cranial-completion-registration,temporal-completion-review}.json`. Совмещение Z-Anatomy с BodyParts3D и автоматическая замена решётчатой кости версией 4.3 отклонены: совпадение общей поверхности не подтверждает форму каждого мелкого образования.
- `research/new-skull-source-audit.json` хранит новый аудит BoneHub Visible Human, NIH 3D, MUG500+ и других источников. Полученные исследовательские сетки и маски не заменяют опубликованные модели и не снимают ограничения автоматически. В отчёте сохранять проверку контрольных сумм, лицензию каждого набора, реальное разделение костей и степень подтверждения конкретных образований; `research/cache/new-skull/` не публиковать автоматически.
- `scripts/new_muscle_source_audit.py` вычисляет из `head_muscles.py` и `manifest_head.py` перечень 9 целых экземпляров мышц и 10 экземпляров частей без отдельной геометрии; отчёт — `research/new-muscle-source-audit.json`. Две стороны считаются отдельно. Кандидат с совместимой объявленной лицензией не считается готовой моделью до получения исходного файла и проверки конкретных объектов. Не извлекать закрытые ресурсы веб-просмотрщиков вместо разрешённого автором скачивания.
- `scripts/export_skull_completion.py` после генерации всех наборов обновляет `research/skull-completion-status.json`: актуальные счётчики, перечень 182 проекций и 14 мест вариантов по костям, 9 отсутствующих моделей мышц и 10 частей, учебные группы, собственные маркеры дополнительных моделей и `complete_skull_geometry_claim: false`. Каталог вариантов сверяется с исходной разметкой; учебных групп должно быть ровно восемь. Не заменять проверку геометрии изменением флагов.
- После изменений: `python scripts/make_head_data.py`, `python scripts/make_pins_head.py`, `python scripts/export_head_evidence.py`, `python scripts/make_skull_study.py`, `python scripts/export_skull_completion.py`, `python verify/verify_ta98.py`, `python verify/verify_head.py`, `python verify/verify_head_positions.py`, `python scripts/make_local.py site/index.html site/local.html`, `node tools/verify-atlas.mjs`. `verify_head_positions.py` проверяет расстояние маркеров до назначенной кости (допуск 0,3 мм) и сохраняет `verify/head-position-geometry.json`; это геометрическая проверка, а не доказательство правильного анатомического названия или независимости источников.
- Для расстановки: `node tools/head-review.mjs` запускает локальный pintool на порту 8774. Он исполняет файлы `qhead/*.job`, сохраняет JSON и снимки; `qhead/_STOP` завершает процесс. Это локальный инструмент разработчика, не публичный сервер.
- Публикация: источник `site/index.html` остаётся фрагментом. `python scripts/package_site.py dist` формирует обычный `dist/index.html`. Репозиторий: `Moveath/myologiya-3d`, сайт: `https://moveath.github.io/myologiya-3d/`.

## Цвета костей и дополнительные модели черепа

- В основном атласе `state.boneColors` включён по умолчанию и сохраняется в `prefs.boneColors` (`localStorage.myo3d`). Палитра задаётся по типу кости, без суффикса стороны: обе одноимённые кости имеют одинаковый учебный цвет. Кнопки «Цвета костей» и «Легенда» действуют только в разделе головы; тест временно отключает цветовые подсказки. Различать палитру, цвет выделения и диагностические/анатомические характеристики — учебная раскраска не является фактом о тканях.
- `state.headCut` и `updateHeadCut()` управляют срезом основной модели головы по X/Y/Z; `renderer.clippingPlanes` и `pointClipped()` должны использовать одну плоскость и знак. Отсечённые поверхности исключаются из выбора и проверки перекрытия маркеров. Для среза нужны обе стороны треугольников, в том числе у ghost-материалов. Тест временно выключает срез; раскрытие панели пересчитывает размещение камеры с учётом уменьшенной видимой области. Переход к точке за срезом отключает его. Срез не создаёт отсутствующие стенки каналов и не является КТ-изображением.
- `site/skull-study.html` — вход через кнопку «Учебные группы»; `site/skull-regions.js` задаёт восемь групп: кости черепа, основание, глазницы и полость носа, пазухи и ячейки, челюсти, ухо и височная кость, мышцы, варианты. Пресеты выбирают существующие объекты, ракурс, срез и прозрачность; геометрию не создают. `scripts/make_skull_study.py` генерирует `site/skull-study-variants.json` из 14 записей `variant` основного атласа. Это каталог типичных мест, не подтверждённые сетки вариантов.
- Превью учебных групп — рендеры опубликованных сеток: `node tools/verify-skull-study.mjs --previews-only`, затем `python scripts/package_skull_previews.py`. Атрибуции изображений сохранены в `site/LICENSE-MODELS.txt`. Параметр `entry=local` сохранять при переходах внутри самостоятельного локального просмотра; для вложенного окна возврат выполняется сообщением родителю.
- `node tools/verify-skull-study-navigation.mjs` проверяет отложенную загрузку вариантов после смены панели, сохранение локального входа, внутреннюю сторону боковых срезов и включение маркера при переходе из каталога с ранее выключенными точками. Отчёт: `verify/ui-skull-study-navigation-report.json`.
- `site/skull-detail.html` — самостоятельный просмотр Z-Anatomy, микро-КТ Halle и OpenEar, доступный из учебных групп и ссылок на отдельные ориентиры. Учебные группы и подробный просмотр используют `#headDetailDialog` через iframe, сохраняя состояние основного атласа. Параметр `embed=1` включает возврат через `postMessage`; родитель проверяет origin и source. Независимая кнопка закрытия в родителе должна работать даже при ошибке загрузки iframe/CDN. Параметры `mode`, `part`, `marker` открывают соответствующий источник, структуру или отдельно проверенный ориентир.
- Файлы GLB загружаются непосредственно. Выбор, скрытие, изоляция, прозрачность и срез работают внутри текущего независимого набора. Не накладывать маркеры BodyParts3D без подтверждённой регистрации и повторной проверки каждого ориентира.
- Самостоятельные учебные группы разрешены: обязательная регистрация всех образцов на основной череп не требуется. Полноту каждого образования проверять на его собственной исходной сетке, отдельно от удобства группировки и наличия карточки. Новая точка на OpenEar или Z-Anatomy не меняет статус проекции на BodyParts3D.
- `site/skull-z-detail.glb` содержит ровно 22 узла `b|<id кости>` и 8 узлов `o|<id полости>`. Метаданные `site/skull-z-detail.json` содержат русские названия, TA98, латынь, источники, лицензии и ограничения. Воздушные полости представлены отдельными авторскими поверхностями/объёмами, а не костной тканью. Их цветные формы нужно подписывать соответствующим образом.
- `scripts/inspect_z_detail.py` извлекает вычисленную геометрию из локального `research/cache/Z-Anatomy/Startup.blend` с `use_scripts=False`. Применяются только имеющиеся у автора модификаторы: шесть операций вычитания решётчатых ячеек и их подразделение поверхности. При отрицательном определителе мировой матрицы объекта порядок вершин треугольника разворачивается, чтобы компенсировать отражение; координаты не меняются. Не добавлять предположительные каналы. `scripts/package_z_detail.py` переводит оси `[x,y,z] → [x,z,-y]` в метрах и выпускает GLB с метаданными. Это смена осей, не регистрация к BodyParts3D. Подробный отчёт — `build_head/detail_z/provenance.json`; дубликат GLB в этой папке не нужен в публикации.
- В `site/skull-z-detail.json` находятся два независимых маркера челюстно-подъязычной борозды (`A02.1.15.031`) справа и слева. Они выбраны по отдельному осмотру двух сторон Z-Anatomy и содержат источники, исходные экранные выборки и ограничения. Эти точки не входят в 521 маркер BodyParts3D и не меняют его проекции. `selectMarker()` включает сохранённый ракурс и срез; видимость точки учитывает срез и перекрытие сеткой.
- Геометрия Z-Anatomy распространяется по CC BY-SA 4.0 с атрибуциями Z-Anatomy, BodyParts3D и указанного в первоисточнике University of Dundee. Модели внутреннего уха и почки с ограничением NC не экспортируются. Сохранять сведения об изменениях. У решётчатой кости есть изолированные мелкие фрагменты и незамкнутые участки после исходных Boolean-операций; не обозначать их как новые анатомические образования.
- `scripts/build_skull_microct.py` строит промежуточную `build_head/detail_microct/skull-microct-hi.glb` и `site/skull-microct.json` из полуавтоматической сегментации Halle (Thomas Kirchner; Zenodo 6108435; CC BY 4.0). Финальная геометрия для сайта — `site/skull-microct.glb`. Контрольная сумма исходника проверяется, данные распаковываются и обрабатываются по блокам. Исходный шаг 0,125 мм, текущая выборка 0,25 мм, затем упрощение meshoptimizer. Ни шаг, ни параметр ошибки упрощения не являются оценкой анатомической точности.
- Микро-КТ — отдельный препарат без нижней челюсти, с подготовительным распилом и описанным автором трепанационным дефектом. Бинарная маска не разделяет отдельные кости. Ориентацию проверять по видимой анатомии и описанию препарата: исходная декларация LPS имеет известное расхождение, поэтому нельзя слепо доверять заголовку NRRD. Экранный срез отсекает поверхность сетки, не является изображением плотностей КТ и не доказывает форму утраченных мелких деталей.
- OpenEar (Sieber et al.; Zenodo 1473724; CC BY 4.0): `scripts/complete_temporal_openear.py` получает выбранные члены оригинального `ZETA.zip` по HTTP byte ranges и проверяет CRC32 каждого члена; MD5 полного архива не выдаётся за проверенный. `scripts/complete_temporal_models.py` сохраняет 12 исходных PLY и строит поверхность `Bone.nrrd` при шаге маски 0,125 мм (пересчёт из CBCT с исходным шагом 0,25 мм), без разрежения объёма и без децимации. `scripts/complete_temporal_data.py` формирует описания и два независимых анатомических источника на структуру. Итоговые файлы: `site/skull-openear.glb` (21 270 896 байта, 13 объектов) и `site/skull-openear.json`; отчёт — `build_head/complete_temporal/geometry-report.json`.
- Для OpenEar маска LPS переводится в RAS авторских PLY, затем ко всем объектам применяется общая правильная ротация `[RASx,RASy,RASz] → [-RASx,RASz,RASy]` и мм → м, без отражения. Направления координат образца не следует автоматически называть анатомическими видами тела: препарат ориентирован произвольно относительно сканера; для ориентиров сохраняются собственные векторы камеры. Упаковка meshopt использует 16-битное квантование координат. Это отдельный правый препарат ZETA, не регистрация к BodyParts3D. Названия и ограничения составных объектов `Scala Vestibuli` и `Sinus Dura` сохранять; не выдавать нерв/артерию за стенки костного канала, а плоскую границу подготовленного блока — за анатомическую поверхность.
- `scripts/openear_landmarks.py` формирует `pins_head/openear-native.json` из `build_head/openear_landmarks/picks.json`: ровно 8 отдельно проверенных маркеров TA98 на 3 слуховых косточках OpenEar ZETA (3 на молоточке, 3 на наковальне, 2 на стремени). Сохранять собственные координаты, `refs`, `nomenclature`, `geometryRefs`, виды и ограничения; не переносить их на BodyParts3D. Отчёт — `research/openear-landmark-review.json`, геометрическая проверка и 7 изображений — `build_head/openear_landmarks/`. Это частичный набор; оставшиеся отростки и ножки, костные каналы и апертуры не объявлены завершёнными. Выполненное сопоставление с двумя атласами не выдаётся за внешнюю экспертную рецензию.
- `scripts/make_skull_study.py` также публикует этот исходный набор в `site/skull-openear-landmarks.json`. Подробный просмотр загружает объединённый `site/skull-native-features.json`, который включает этот набор и новые ориентиры; файл `site/skull-openear.json` продолжает описывать исходные 13 объектов. После изменения собственных ориентиров выполнить `python scripts/openear_landmarks.py`, затем `python scripts/make_skull_study.py` и `python scripts/export_skull_completion.py`.
- После правок отдельного просмотрщика: `node tools/verify-skull-detail.mjs`. Проверять все три модели, загрузку/ошибку/повтор, срезы, выбор, прозрачность, маркеры Z-Anatomy и OpenEar и возврат в атлас на 390/1280 px в обеих темах; отчёт — `verify/ui-skull-detail-report.json`, снимки — `shots/head-detail/`. Учебные группы проверяет `node tools/verify-skull-study.mjs`. Эти проверки интерфейса не подтверждают анатомическую полноту. Лицензии и изменения всех опубликованных моделей также перечислены в `site/LICENSE-MODELS.txt`.
- Дополнительные модели не изменяют статус основного набора: 521 маркер, 325 `surface`, 182 `projection`, 14 `variant`. Полная геометрическая реконструкция всех мелких образований пока не подтверждена. Для девяти карточек мышц головы отдельная геометрия по-прежнему отсутствует; общий охват составляет 52 карточки и 43 моделируемых экземпляра. Ещё 10 экземпляров частей не имеют отдельных сеток: глубокая часть и ресничный пучок круговой мышцы глаза с двух сторон (4), поперечная и крыльная части носовой мышцы с двух сторон (4), краевая и губная части круговой мышцы рта (2).

### Проверка конкретных образований и изображений вариантов

- `pins_head/face-features-bp.json` добавляет шесть повторно осмотренных участков обеих верхних челюстей; файл включён в `head_localization.SUPPLEMENTS`. Генератор — `scripts/face_features_export.py`. Различать резцовую часть и сохраняющийся резцовый шов: часть может быть сращена с остальной костью, отсутствие шва не доказывает её отсутствие.
- `scripts/make_skull_features.py` объединяет прежние два ориентира Z-Anatomy, восемь ориентиров косточек и `pins_head/{face,cranial,temporal}-native-features.json`. Получаются `site/skull-native-features.json`, `site/skull-feature-catalogue.json` и `site/skull-evidence-index.js`; их руками не редактировать. Просмотрщик загружает объединённый реестр и выбирает только свой `mode`. У маркера обязательны собственные координаты, ракурс, источники и ограничение; `scope` различает участок поверхности, апертуру, часть стенки и объём воздуха.
- `scripts/variant_examples.py` упаковывает 12 целых авторских рисунков, проверенных визуально и по подписям, для 12 разных кодов / 14 карточек вариантов. Файлы `skull-example-*`, `skull-variant-examples.json`, `LICENSE-SKULL-EXAMPLES.txt` публикуются; полный кэш статей — нет. Указывать лицензию каждого изображения, автора, статью, номер рисунка и изменения. Это изображения других препаратов, не подтверждение геометрии BodyParts3D и не новые 3D-сетки. Номенклатура, анатомические сведения и конкретный опубликованный случай остаются разными видами свидетельств.
- В `complete_temporal_models.py` не возвращать лишнюю перестановку `f[:,[0,2,1]]`: вместе с перестановкой осей zyx→xyz она обращала нормали костного блока внутрь. Направление проверяется по значениям исходной маски по обе стороны поверхности, а не только видом освещения. Отчёт — `build_head/temporal_features/winding-verification.json`.
- После изменений повторить генераторы, проверки TA98/головы/координат и `node tools/verify-skull-features.mjs` на 390/1280 px в обеих темах. Проверять загрузку изображений, источники, поиск, прямые переходы и видимость каждого нативного маркера. Файлы больших исследовательских ROI (`build_head/cranial_features/*.glb`, `*.npy`) в публикацию не включать.


## Исходные стенки каналов и КТ

- `site/skull-detail.html?mode=channels` открывает выбранные костные стенки OpenEar; `site/skull-scan-viewer.js` показывает настоящие косые срезы, отдельно от экранного отсечения 3D-сетки. Смена серии и ошибка загрузки обязаны очищать старое изображение. Подпись источника и шага съёмки берётся из конкретного кадра: embedded и unembedded CBCT нельзя смешивать под одной точностью.
- Генерация OpenEar: `scripts/temporal_channels_{oblique,build,slices,package,check}.py`. Экспорт сохраняет существующие треугольники маски, не заполняет разрывы и не строит стенки из модели нерва/артерии. Утверждение о полном канале независимо от количества срезов и длины направляющей. Проверка — `research/temporal-channel-review.json` и `pins_head/temporal-channels.json`.
- `scripts/package_skull_channels.py` проверяет SHA-256 и копирует выбранные GLB/атласы срезов в site. Не публиковать исходные многогигабайтные КТ или кэш сторонних публикаций. Лицензии производных сохранять отдельно от кода сайта.
- `scripts/make_skull_features.py` добавляет `channel_views` в каталог по TA98, отдельно от `views` точечных ориентиров. Они не меняют 521 маркер BodyParts3D или 31 собственный маркер других сеток. `scripts/export_skull_completion.py` сохраняет отдельный раздел `source_channel_geometry`.
- После изменений: `node tools/verify-skull-channels.mjs`, затем затронутые проверки detail/study/features. Проверять 390/1280 px и обе темы, источники срезов, переключение объектов, отключение контекста и отсутствие старого КТ под названием другой структуры.
- `research/muscle-completion-review.json` отражает повторную проверку 9 мышц и 10 частей. ArtiSynth OOM/OOP — перекрывающиеся расчётные области одного полулица, а не доказанные две части TA98. Наличие файла с подходящим именем не закрывает недостающую геометрию.

- `mode=cranial_channels` использует отдельные исходные Halle КТ/маску и `scripts/cranial_channels_package.py`. 112 срезов показывают проверенный ход canalis nervi hypoglossi (A02.1.04.016) между апертурами, при `completeFeatureGeometry:false`. Обе полные MD5 проверены. `frames.center_m/u/v` уже в координатах Three; повторно преобразовывать их нельзя. Плоскость КТ — учебный overlay, не анатомическая поверхность.
