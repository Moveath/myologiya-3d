# AGENTS.md — правила работы с «Миология 3D»

## Перед началом
- Прочитай нужные разделы `README.md`: цель, правила точности, текущий объём и бэклог.
- Этот файл содержит рабочие ограничения; не дублируй здесь историю выпусков и каталоги README.
- Проверяй фактический код и генераторы: исторические описания могут относиться к прежнему интерфейсу.
- Читай только относящиеся к задаче файлы; сначала ищи пути и символы через `rg`.
- Делай точечные изменения, не переформатируй посторонние файлы и не выводи большие логи/base64.
- Не устанавливай и не обновляй зависимости без необходимости; сначала проверь доступное окружение.
- Загружай только нужный skill: `anatomy-validator` для фактов/терминов, `mesh-auditor` для сеток, `threejs-optimizer` для производительности; не все три на обычную правку.
- Уже прочитанные неизменённые инструкции не перечитывай. Независимые поиски объединяй; ограничивай вывод нужными диапазонами, сохраняй длинные отчёты в файлы.
- MCP вызывай для конкретной проверки, не для ритуального опроса всех подключений. Context7: один resolve на библиотеку в задаче, затем запросы только по недостающим API; результаты сверяй с r170.
- Для UI используй Playwright; другие браузерные инструменты — при недоступности или неподдерживаемой операции. Предпочитай точечный поиск/DOM-проверку полному снимку; снимки нужны для визуальной оценки.
- Не повторяй успешные тесты без новых изменений или нерешённого риска. Сокращай вывод и повторные действия, а не проверку источников, геометрии и регрессий.
- Исторические MCP-сценарии из `research/` запускай через `node tools/prepare-evidence-mcp.mjs <путь>`: он выдаёт новый сценарий с отдельными путями снимков. Новые результаты сохраняй через `tools/evidence-run.mjs` (уникальный каталог, запрет перезаписи); старые JSON/PNG не обновляй.
- Перед задачей найди связанные ID в [ANATOMY_ISSUES.md](ANATOMY_ISSUES.md); после каждой задачи обнови статусы/новые находки и добавь изменения, проверки, остаток и прогресс этапа в [ANATOMY_PROGRESS.md](ANATOMY_PROGRESS.md). Соблюдай правила учёта и порядок восьми этапов из этих файлов: не дублируй задачи, не меняй ID, не удаляй историю и не закрывай без доказательств; в конце ответа сообщай число проверенных, незакрытых и заблокированных записей, отдельно от числа структур.

## Карта проекта
- `site/index.html` — основной интерфейс, CSS и JS-модуль; это фрагмент без обёртки HTML.
- `site/local.html` генерируется: `python scripts/make_local.py site/index.html site/local.html`.
- `site/skull-detail.html` — дополнительные модели; `skull-study.html` — учебные группы.
- `site/atlas-{performance,controls,runtime}.js` — ускорение, управление и обработка отказов.
- `scripts/` — Python-генераторы, манифесты структур, источники карточек и упаковщики.
- `pins*/` — исходная разметка; `build*/` — промежуточные модели, выборки и инструменты разметки.
- `research/` — источники, происхождение моделей, ограничения и результаты анатомического аудита.
- `verify/` — Python-проверки и отчёты; `tools/verify-*.mjs` — Node/Playwright-проверки.
- `shots/` — снимки проверок; `site/vendor/` — локальные библиотеки с лицензиями и хешами.
- `tools/package.json` и `tools/package-lock.json` задают Node-зависимости; корневого npm-проекта нет.
- Lockfile: Three.js 0.170.0, three-mesh-bvh 0.8.3, gltfpack 1.3.0, Playwright 1.63.0.
- Проверки геометрии: `.venv/Scripts/python.exe`, закрепления — `verify/requirements-geometry.txt`; создание из существующего Python 3.12 — `verify/setup-geometry.ps1 -Python <путь>`. Остальные зависимости выбирай только по нужному скрипту.

## Инструменты и Three.js
- Для работы с 3D-геометрией используй Blender MCP; воспроизводимые экспорты сохраняй в конвейере проекта.
- Для интерактивного тестирования интерфейса используй Playwright MCP вместе с существующими проверками.
- Для документации библиотек используй Context7; документация не заменяет анатомические источники.
- Если нужный MCP недоступен, сообщи об ограничении; не заявляй, что проверка выполнена.
- Целевая версия Three.js — строго **0.170.0 (r170)**, включая OrbitControls, GLTFLoader и декодер.
- В Context7 уточняй версию; примеры из `dev`/latest проверяй по исходникам r170 и локальному vendor.
- Если Context7 не даёт r170, подтверждай API по закреплённым исходникам; не переноси новые API вслепую.
- Не обновляй Three.js/BVH попутно и не смешивай версии core/addons или CDN и локальные копии.
- `scripts/package_three.py` проверяет 0.170.0; `scripts/package_bvh.py` упаковывает BVH с лицензией.
- Vendor не исправлять вручную; изменения управления вносятся в `site/atlas-controls.js`.

## Неприкосновенность моделей и данных
- **Никогда не изменяй и не перезаписывай оригинальные GLB без явного разрешения пользователя.**
- Это относится и к GLB в base64 (`site/*-glb.txt`), резервным моделям и перезаписи через упаковщики.
- До разрешённой обработки сохрани исходник; производные создавай отдельно, фиксируя метод и хеши.
- Не децимируй кости; при разрешённой сборке сохраняй все исходные треугольники и проверяй результат.
- Не меняй геометрию ради ускорения; сохраняй имена узлов, иерархию, стороны и систему координат.
- BodyParts3D мм → Three.js м: `(x, y, z) = (bp.x, bp.z, -bp.y) / 1000`; справа у тела — отрицательный X.
- Узлы: `m|мышца|часть`, `b|кость`, `o|структура`, `c|id`; gltfpack может хранить имя на родителе.
- Не редактируй генерируемые `pins*.js`, региональные `data-*.js` и JSON вручную: найди их генератор.
- Карточки головы/шеи/груди: `scripts/{head,neck,thorax}_{muscles,terms}.py`; контекст: `context_bone_cards.py`.
- Используй только открытые совместимые источники; сохраняй атрибуцию и лицензии конкретных производных.
- BodyParts3D — CC BY-SA 2.1 Japan; лицензия кода не заменяет лицензии моделей и изображений.

## Анатомическая достоверность
- Интерфейс и описания — по-русски, латынь — TA98; не выдумывай названия, координаты и прикрепления.
- Каждое новое анатомическое утверждение сверяй минимум с двумя независимыми источниками.
- Не выдумывай научные ссылки и локаторы; разногласия сохраняй в `note`/описании, неизвестное обозначай явно.
- Два издания номенклатуры не являются двумя независимыми подтверждениями точной топографии.
- Каталоги сверяй с `scripts/ta98.py` и региональными таблицами применимости; не добавляй фиктивные точки.
- Сохраняй `localization`/`loc`, `evidence`, `refs`, `modelNote`, статусы и область применимости доказательств.
- Поверхностный маркер не доказывает полную форму или площадь прикрепления; сведения целой мышцы не приписывай части.
- Не зеркаль координаты без независимой проверки; координаты другого образца не переноси автоматически.
- Сохраняй записи без геометрии/координат и ограничения, включая неподтверждённую топографию `crista costae`.
- `skull-education.html` сейчас показывает учебные виды/объяснения без 3D; исторические схемы не возвращай без запроса.
- Перед заявлением полноты головы проверь `research/skull-closure-requirements.{html,json}`; UI-тест не заменяет анатома.

## Выбор, BVH, срезы и навигация
- Сохраняй поведение `register/select/goTo`, групп/частей, маркеров, raycasting и видимости 0/1/2.
- BVH строится только с `indirect:true`: индексы, вершины и `faceIndex` должны оставаться неизменными.
- При активном срезе `firstHitOnly` выключен; выбор и occlusion фильтруются через `pointClipped()`.
- Плоскость и знак отсечения должны совпадать у рендера и лучей; сохраняй видимость обеих сторон среза.
- Срез сетки не является КТ и не создаёт стенки каналов; КТ другого источника не оставляй под новой подписью.
- Сохраняй lazy loading, восстановление разрешения после движения и обработку WebGL/contextlost/retry.
- `state.context` независим от изоляции; не теряй владельцев контекстных костей и доступ к их карточкам.
- До 899 px панели закрываются без изменения выбора/ракурса; не дублируй id и обработчики кнопок.
- Сохраняй параметры region/entry/theme/embed и выбор при переходах; iframe-сообщения проверяй по origin/source.

## Проверки после изменений
- Запускай подходящие существующие проверки; `npm test` в `tools` — заглушка, а не тестовый набор.
- После изменения основного HTML сначала пересоздай `site/local.html` командой выше.
- Анатомические данные: соответствующий генератор и `python verify/verify_ta98.py` (3 известных расхождения).
- Голова: `python verify/verify_head.py`; координаты: `python verify/verify_head_positions.py`.
- Шея/грудь: `python verify/verify_neck_positions.py` / `verify_thorax_positions.py`, соответствующие `tools/verify-*-data.mjs`.
- Основной UI: `node tools/verify-atlas.mjs`; навигация: `node tools/verify-navigation.mjs`.
- BVH/срезы: `node tools/verify-atlas-performance.mjs`; управление: `node tools/verify-atlas-touch.mjs`.
- Мобильный UI: `node tools/verify-mobile-layout.mjs`; подробный просмотр: `node tools/verify-skull-detail-mobile.mjs`.
- Дополнительные модели: `node tools/verify-skull-detail.mjs`; остальные `verify-skull-*.mjs` выбирай по затронутой функции.
- Контекст/регионы: `verify-context-bone-models.mjs`, `verify-neck.mjs`, `verify-thorax.mjs` в `tools/`.
- Проверяй 390 и 1280 px, светлую и тёмную темы, реальные клики, ошибки консоли и снимки.
- Для Chromium доступен `ATLAS_CHROMIUM`; эмуляцию не выдавай за физический телефон или GPU-бенчмарк.
- При правке только документации проверь текст и ссылки; пересборка моделей и UI-тесты не нужны.
- Кратко сообщай, что изменено, какие проверки прошли и что не проверено с указанием причины.
