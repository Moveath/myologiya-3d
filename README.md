# Миология 3D — учебный 3D-атлас анатомии

Интерактивный 3D-атлас мышц и костей на русском языке с латинскими названиями. Делается для студента-медика, который хочет стать хирургом, поэтому главное требование — **анатомическая точность**: новые утверждения должны быть проверены по источникам, латынь и список образований костей — по международной анатомической терминологии (Terminologia Anatomica, TA98). Текущие ограничения раздела головы перечислены ниже.

Публичный сайт: **https://myologiya-3d-egor.nifty-spool-0531.chatgpt.site/**

Копия на GitHub Pages: https://moveath.github.io/myologiya-3d/

Исходники: https://github.com/Moveath/myologiya-3d

На Windows можно запустить файл **«Открыть атлас.cmd»** (нужен Python 3).

Локально: `cd site && python3 -m http.server 8000`, затем открыть http://localhost:8000/local.html (нужен интернет: three.js и шрифты грузятся с CDN).

## Задание (что это за проект и что нужно делать)

Сделать бесплатный учебный атлас, похожий по возможностям на приложение «Anatomy 3D Atlas» (Catfish Animation Studio), но **своими силами и только из открытых данных**: ничего не копировать из платных приложений (ни моделей, ни текстов), приложение — только ориентир по функциям.

Что должно быть у атласа:
1. Разделы тела (голова, шея, туловище, верхняя конечность, таз и нижняя конечность) и подразделы внутри них — так, чтобы разобрался даже человек без медицинского образования.
2. 3D-модель, которую можно крутить и приближать; нажатие на мышцу или кость открывает карточку.
3. Мышцы — с отдельными частями и головками (у дельтовидной 3 части, у двуглавой 2 головки и т. д.). Карточка мышцы: начало, прикрепление, функция, иннервация, кровоснабжение, примечания.
4. Кости — с точками-ориентирами. **На каждой кости ровно столько точек, сколько терминов в официальном списке TA98 для этой кости** — без пропусков и без лишних. У каждой точки: русское название, латынь, код TA98, понятное описание, какие мышцы здесь начинаются/прикрепляются. Непостоянные образования помечены по анатомическим источникам; скобки TA98 сами по себе не доказывают непостоянство. Места прикрепления мышц, у которых нет своего термина, показываются отдельно и в счёт не входят.
5. Режим теста, поиск по списку (по-русски и по-латыни), словарик терминов, слои (снятие мышц по глубине), светлая и тёмная тема, нормальная работа на телефоне.
6. Правила точности:
   - данные по мышцам сверять минимум с двумя независимыми источниками; где русские и англоязычные учебники расходятся — писать об этом прямо в карточке, а не выбирать молча;
   - латынь — по TA98; русские термины — по русскому изданию «Международная анатомическая терминология» (под ред. Л. Л. Колесникова, 2003), старые учебные названия — в скобках/описании;
   - список TA98 по костям проверяется скриптом (см. AGENTS.md), а не вручную;
   - честно помечать, где на модели чего-то нет (например, непостоянные косточки) или где точка условно ставится на линию/поверхность.

## Что делать дальше (бэклог, по приоритету)

1. **Завершить подтверждённую геометрию образований черепа.** Все 521 записи TA98 имеют маркеры и топографические описания по двум независимым источникам. Разрешены самостоятельные учебные группы и разные исходные образцы: совмещать все сетки с BodyParts3D не обязательно. Для каждого отверстия, канала, борозды или ости всё равно нужно проверить собственную геометрию и поставить ориентир на соответствующей сетке. На основном черепе остаются 182 проекций; подтверждение образования на другом образце само по себе не меняет их статус. Для 14 мест вариантов нужны отдельные образцы, где вариант действительно присутствует. Также остаются 9 целых экземпляров мышц без модели и 10 экземпляров частей мышц без отдельной геометрии.
2. **Раздел «Мочеполовая система».** В BodyParts3D есть почки, мочевой пузырь, мочеиспускательный канал и мужские половые органы (яички, придатки, семенные пузырьки, предстательная железа, половой член). Женских органов в этих данных нет — нужно найти открытые модели с совместимой лицензией. Термины и описания — по главам «Мочевая система» и «Половые системы» TA98.
3. **Продолжение головы, шея и туловище** — завершение перечня проверенных образований слуховых косточек в самостоятельной группе OpenEar (сейчас размечено 8), мышцы глазного яблока, языка и глотки, затем новые области по тем же правилам. Перенос на основной череп допустим только при отдельном подтверждении соответствия и не обязателен для независимого просмотра.
4. **Пометка «для экзамена»** — если будет список кафедры, отметить нужные точки/мышцы и добавить фильтр.
5. **Тест по точкам на костях** (показывается точка — выбрать название).
6. Суставы и связки, затем сосуды и нервы.

## Голова: объём и ограничения

Добавлены обе стороны восьми парных и шесть непарных костей черепа, мимические и жевательные мышцы. Стиль, слои, поиск на русском и латыни, карточки, выделение частей и тест сохранены. Для головы есть шесть стандартных ракурсов. Зубы показаны как контекст, без отдельных карточек. Три слуховые косточки доступны в независимом образце OpenEar; в основную модель BodyParts3D они не перенесены.

В голове по умолчанию включён режим **«Цвета костей»**. Каждому типу кости назначен постоянный учебный цвет; правая и левая одноимённые кости окрашены одинаково. Это условная раскраска для запоминания. Переключатель возвращает обычный цвет костной ткани, а «Легенда» показывает названия и позволяет выбрать кость. Настройка сохраняется в браузере; на время теста раскраска отключается. Чтобы видеть весь цветной череп, нужно выбрать слой «Кости».

Номенклатурная полнота и геометрия проверяются отдельно. В каталоге каждой кости ровно её список TA98. **Все 521 записи имеют 3D-маркеры и описания с двумя независимыми анатомическими источниками.** Тип локализации виден в карточке:

- **325 маркеров на поверхности** — выбран участок видимого образования, поверхности или края отверстия. Один маркер не изображает всю его протяжённость.
- **182 анатомические проекции** — источники подтверждают положение образования, но его мелкий рельеф или просвет нельзя достоверно различить на сетке BodyParts3D. Маркер показывает ожидаемую область, а не доказывает наличие отверстия, борозды или канала в геометрии.
- **14 мест вариантов** — показана типичная область непостоянного образования; его наличие у человека, по которому создана модель, не установлено.

Таким образом, охват маркерами полный, а точная геометрия мелких образований остаётся ограничением модели. Внутрикостные каналы не реконструированы из одиночной точки; расхождения анатомических источников сохранены в примечаниях. Парные кости проверены по отдельным сеткам обеих сторон.

При повторном осмотре шесть прежних проекций заменены проверенными точками на уже существующем рельефе BodyParts3D: верхнечелюстной отросток нижней носовой раковины, слёзная борозда слёзной кости и раковинный гребень нёбной кости — каждый с обеих сторон. Координаты, метод выбора и два источника для каждого образования сохранены в `pins_head/face-completion.json`. Сами костные сетки при этом не дорисовывались.

**«Срез черепа»** работает непосредственно на основной модели: три плоскости, положение и выбор сохраняемой стороны. Удалённые срезом поверхности не перехватывают нажатия и не закрывают маркеры. Срез показывает существующую 3D-сетку, не создаёт стенки отсутствующих каналов и не является томографическим снимком.

Кнопка **«Учебные группы»** открывает `site/skull-study.html` с восемью направлениями: «Кости черепа», «Основание черепа», «Глазницы и полость носа», «Пазухи и ячейки», «Челюсти», «Ухо и височная кость», «Мышцы головы», «Варианты строения». Готовые виды используют существующую геометрию, изоляцию структур, прозрачность и срезы. Группа мышц возвращает к карточкам основного атласа. Каталог вариантов содержит 14 уже описанных типичных мест; отдельные сетки вариантов в него не добавлены. Из учебных групп можно открыть подробный просмотр и вернуться к прежнему состоянию атласа.

Подробный просмотр `site/skull-detail.html` сохраняет три независимых источника:

- **«Кости и пазухи» — Z-Anatomy, CC BY-SA 4.0.** В модели 22 отдельные кости и 8 объектов воздушных полостей: лобная и клиновидная пазухи, передние, средние и задние решётчатые ячейки с обеих сторон. Цветные формы пазух показывают воздушное пространство, а не кость или ткань. Есть выбор, скрытие и изоляция структур, прозрачность и срез. Выполнены исходные авторские операции вычитания ячеек решётчатой кости; новые отверстия по догадке не создавались. Геометрия остаётся учебной и упрощённой, с открытыми краями и небольшими артефактами сетки. Полные мелкие каналы не заявлены.
- **«Микро-КТ» — отдельный препарат Halle, CC BY 4.0.** Поверхность построена из опубликованной сегментации костной ткани. У образца отсутствует нижняя челюсть, имеется подготовительный распил и описанный автором небольшой трепанационный дефект правой теменной кости. Их нельзя принимать за обычные анатомические отверстия. Кости в исходной бинарной маске не разделены. Исходный шаг вокселя — **0,125 мм**, шаг выборки для браузерной поверхности — **0,25 мм**, затем сетка дополнительно упрощена. Эти числа обозначают этапы обработки и **не являются гарантией точности**; самые мелкие детали могут быть утрачены. Срез в просмотрщике отсекает поверхность 3D-сетки, а не показывает плотности томографического изображения.
- **«Височная кость» — OpenEar, образец ZETA, CC BY 4.0.** В одном исходном пространстве показаны **13 объектов**: костный блок и 12 авторских сегментов, в том числе три слуховые косточки. Два объекта объединяют несколько образований: `Scala Vestibuli` и `Sinus Dura`; их компоненты отдельно не сегментированы. Поверхность блока получена из авторской маски `Bone.nrrd` при шаге маски **0,125 мм** (маска пересчитана из CBCT с исходным шагом **0,25 мм**), без разрежения объёма и без децимации сетки; выполнены преобразование осей, перевод в метры и сжатие meshopt с квантованием координат. Авторские PLY сохраняют собственную геометрию. Это отдельный препарат, не замена височным костям BodyParts3D. Нерв и артерия показываются как самостоятельные сегменты, а не как подтверждение стенок костных каналов. Плоские границы обрезанного блока не являются анатомическими образованиями.

В Z-Anatomy отдельно проверены два маркера челюстно-подъязычной борозды нижней челюсти — справа и слева. Они имеют собственные координаты и ссылки и доступны из соответствующей карточки основного атласа. Подтверждение этого рельефа на Z-Anatomy не меняет статус той же записи на BodyParts3D.

В OpenEar ZETA отдельно проверены **8 поверхностных ориентиров**: головка, шейка и рукоятка молоточка; тело, длинная и короткая ножки наковальни; головка и основание стремени. У них собственные координаты, коды TA98, виды и по два независимых анатомических источника. Это частичный набор: он не закрывает полный перечень образований слуховых косточек или неподтверждённые каналы височной кости. Выборки и ограничения сохранены в `pins_head/openear-native.json` и `research/openear-landmark-review.json`; выполнены осмотр из нескольких направлений и геометрическая проверка, внешняя экспертная рецензия анатома не заявляется.

У дополнительных моделей собственные координаты. Они не совмещены с BodyParts3D, и точки основного атласа на них не перенесены. **Основной череп имеет 521 маркер: 325 на поверхности, 182 проекций и 14 мест вариантов.** Добавление других моделей не означает, что вся микрогеометрия этих образований завершена. Исследовательское совмещение Z-Anatomy с основным черепом отклонено для публикации: оно оставляет миллиметровые расхождения и не доказывает форму полостей того же образца. Альтернативная решётчатая кость BodyParts3D 4.3 также не принята как автоматическая замена.

История сравнения моделей — `research/head-model-review.json`, подробный реестр поиска и ограничений — `research/skull-detailed-sources.json`. Повторная проверка по областям сохранена в `research/face-completion-review.json`, `research/cranial-completion-registration.json` и `research/temporal-completion-review.json`. Новый поиск BoneHub Visible Human, NIH 3D, MUG500+ и других источников описан в `research/new-skull-source-audit.json`: полученные сетки и маски расширяют исследовательский набор, но пока не подтверждают полный перечень мелких образований или 14 вариантов. Источники, лицензии и изменения опубликованных моделей находятся в `site/skull-z-detail.json`, `site/skull-microct.json`, `site/skull-openear.json` и `site/LICENSE-MODELS.txt`; отдельные маркеры OpenEar — в `site/skull-openear-landmarks.json`.

Актуальный список оставшихся 196 неподтверждённых на основной сетке записей (182 проекций и 14 мест вариантов), сгруппированный по костям, — `research/skull-completion-status.json`; его поле `complete_skull_geometry_claim` остаётся `false`. Отчёт также перечисляет учебные группы, собственные маркеры дополнительных моделей и отсутствующую геометрию мышц и их частей.

У **9 карточек мышц** нет отдельной геометрии в выбранном наборе: передняя, верхняя и задняя ушные мышцы с двух сторон; мышца, опускающая бровь, с двух сторон; поперечная мышца подбородка. Кроме того, без отдельных сеток остаются **10 экземпляров частей**: глубокая часть и ресничный пучок круговой мышцы глаза с двух сторон (4), поперечная и крыльная части носовой мышцы с двух сторон (4), краевая и губная части круговой мышцы рта (2). Эти части доступны в карточках и не считаются дополнительными целыми мышцами. Неустановленные функция и конкретное кровоснабжение поперечной мышцы подбородка явно помечены.

Повторный поиск исходных моделей и условия их использования сохранены в `research/new-muscle-source-audit.json`. Генератор `scripts/new_muscle_source_audit.py` вычисляет недостающие экземпляры из карточек и манифеста моделей. Среди кандидатов есть авторская модель головы Visible Ape Project с объявленной CC BY 4.0, но её исходные файлы ещё не получены и разделение нужных мышц не проверено. Открытые маски Jena3D-FACE не выделяют требуемые мелкие мышцы по отдельности. Эти источники не засчитаны как готовая геометрия.

Русские названия сверены с книгой Колесникова (2003). Сведения о мышцах имеют ссылки в карточках; расхождения источников сохранены в примечаниях. Реестр фактов и источников: `research/head-evidence.json`. IFAA и русское издание одного стандарта подтверждают номенклатуру и **не выдаются за два независимых анатомических учебника**.

Для трёх костных терминов сохранена печатная редакция TA98: `A02.1.03.031` — `septum sinuum frontalium`; `A02.1.05.017` — перегородка клиновидных пазух; `A02.1.05.018` — апертура клиновидной пазухи. Электронная IFAA содержит более позднюю форму первого термина и обратную нумерацию двух последних. Скрипт проверяет эти различия редакций отдельно, затем показывает ровно три прежних расхождения по костям ноги. В мышцах сохранены исходные `m. levator labii superioris alaeque nasi` и код `A04.1.03.012` для `m. depressor septi nasi`.

## Сборка и проверка головы

Готовые модели уже входят в `site/`; для запуска скачивать STL не нужно. Для изменения карточек и повторной проверки:

```powershell
py -3 scripts/make_head_data.py
py -3 scripts/make_pins_head.py
py -3 scripts/export_head_evidence.py
py -3 scripts/make_skull_study.py
py -3 scripts/export_skull_completion.py
py -3 verify/verify_ta98.py
py -3 verify/verify_head.py
py -3 verify/verify_head_positions.py
py -3 scripts/make_local.py site/index.html site/local.html
```

Для проверки интерфейса: `npm --prefix tools ci`, затем из `tools/` выполнить `npx playwright install chromium`; из корня — `node tools/verify-atlas.mjs`. Проверяются 390 и 1280 px, светлая и тёмная темы, карточки, части, поиск, тест, загрузка руки и ноги. Скриншоты и отчёт сохраняются в `shots/head/`. При нестандартном расположении Chromium задайте полный путь в переменной `ATLAS_CHROMIUM`.

Для повторной сборки геометрии используется `scripts/manifest_head.py`: `py -3 scripts/fetch_stl.py manifest_head stl_head`, затем тот же `build_glb.py` и gltfpack, что описаны в AGENTS.md. Кости головы сохранены без дополнительного упрощения исходных STL BodyParts3D 3.0; исходные файлы уже содержат упрощённую геометрию. Обе стороны взяты из отдельных исходных STL. Исходные координаты заданы в `build_head/landmarks_ta.js` и `pins_head/ta.json`. Уточнения и новые выборки — `build_head/landmarks_{face,cranial,temporal}_extra.js` и `pins_head/{face,cranial,temporal}-extra.json`; `scripts/head_localization.py` объединяет их по кости и коду TA98, сохраняя тип локализации и пояснение к модели. Описания и ссылки находятся в `scripts/head_{face,cranial,temporal}_evidence.py`. После пересборки обязательна визуальная проверка каждой кости.

`verify/verify_head_positions.py` проверяет, что опорная точка действительно лежит на назначенной ей сетке с допуском 0,3 мм; результат — `verify/head-position-geometry.json`. Такая проверка обнаруживает смещение и ошибку системы координат, но не подтверждает анатомическое название и не превращает проекцию в видимый рельеф.

Дополнительная модель Z-Anatomy собирается скриптами `scripts/inspect_z_detail.py` и `scripts/package_z_detail.py`; для первого нужен локальный исходный `Startup.blend` и `bpy`. Он открывается с отключённым исполнением встроенных скриптов. При зеркальном преобразовании объекта исправляется порядок вершин треугольников, без изменения их координат. `scripts/build_skull_microct.py` читает исходную бинарную сегментацию Halle, проверяет её контрольную сумму, извлекает и упрощает поверхность. OpenEar загружается скриптом `scripts/complete_temporal_openear.py`, собирается `scripts/complete_temporal_models.py`; метаданные создаёт `scripts/complete_temporal_data.py`. Отдельный набор восьми ориентиров собирается `scripts/openear_landmarks.py` из сохранённых выборок `build_head/openear_landmarks/picks.json`. Исходные элементы ZIP проверяются по CRC32, контрольная сумма полного частично загруженного архива не заявляется проверенной. Исходные архивы и промежуточные файлы находятся в `research/cache/` и не публикуются. Готовые GLB и описания уже входят в `site/`. Каталог вариантов и опубликованный набор ориентиров OpenEar обновляет `py -3 scripts/make_skull_study.py`; после генерации всех наборов обновить общий статус: `py -3 scripts/export_skull_completion.py`. Проверка трёх дополнительных просмотров: `node tools/verify-skull-detail.mjs`; учебных групп: `node tools/verify-skull-study.mjs`.

## Дополнительная проверка образований, 13 октября 2026

Повторный осмотр обеих верхних челюстей подтвердил ещё шесть поверхностных участков: слёзную вырезку, решётчатый гребень и резцовую часть с каждой стороны. Координаты и ограничения сохранены в `pins_head/face-features-bp.json`. Это проверка видимого участка, а не отдельная сегментация всех границ образования.

В «Учебных группах» появился поиск **«Подробные ориентиры»**: он открывает собственные точки дополнительных моделей с сохранёнными крупными планами. Исходники — `pins_head/{face,cranial,temporal}-native-features.json`; объединённый файл — `site/skull-native-features.json`. Края отверстий, участки стенок и авторские объёмы воздуха имеют разные ограничения. Они не объявляются полными реконструкциями каналов и не меняют разметку BodyParts3D автоматически.

Все 12 разных терминов из 14 карточек вариантов получили опубликованные примеры реальных препаратов или КТ. Это **изображения**, а не новые интерактивные сетки. Оригинальные рисунки и авторские обозначения сохранены; русский комментарий расположен отдельно. Источники, лицензии и контрольные суммы — `site/skull-variant-examples.json` и `site/LICENSE-SKULL-EXAMPLES.txt`. Проверка существования варианта в публикации не доказывает его наличие в конкретном образце BodyParts3D.

Генерация: после `scripts/make_skull_study.py` выполнить `scripts/variant_examples.py`, затем `scripts/make_skull_features.py` и `scripts/export_skull_completion.py`. Первому нужен локальный исследовательский кэш открытых публикаций; готовые изображения уже включены в `site/`, сами статьи не публикуются. Дополнительная проверка интерфейса — `node tools/verify-skull-features.mjs`.

В костном блоке OpenEar исправлен обращённый порядок треугольников. Координаты поверхности сохранены; направление нормалей проверено непосредственно по исходной костной маске. Шаг маски 0,125 мм нельзя выдавать за исходное разрешение CBCT 0,25 мм. Отчёт — `build_head/temporal_features/winding-verification.json`.

## Публикация

`main` содержит исходники, `gh-pages` — готовую папку сайта. `py -3 scripts/package_site.py dist` создаёт полноценный `dist/index.html` из фрагмента, копирует данные и модели, добавляет `.nojekyll`. На GitHub Pages публикуется содержимое `dist/`. `scripts/sync_github.py` — резервная публикация через Git Data API при недоступности обычного Git; она использует уже настроенный системный менеджер учётных данных и не сохраняет токены в проекте.
