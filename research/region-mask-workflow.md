# Воспроизводимая разметка областей

Конвейер готовит геометрические кандидаты, но **не устанавливает анатомические границы автоматически**. Он не использует расстояние от пина, зеркалирование, сглаживание или перенос между препаратами.

## Входы и уровни

- `scripts/skull_region_recipes.json`: постоянный ID, существующие pinIds, владелец и сторона, тип представления, источник/лицензия, научные ссылки, ограничение и рецепт. Хеши фиксируют исходную аннотацию и снимки декодированных ресурсов.
- `scripts/skull_region_admissions.json`: отдельное решение для каждого рецепта. Его `recipeHash` вычисляется функцией `digest` из `region_mask_pipeline.py`. Изменённый рецепт требует нового решения; успешный тест его не выдаёт.
- `confirmed`: анатомическая разметка принята **только в явно указанном scope**; нужны доказательства границ того же образца и адресная анатомическая приёмка. Скрипт проверяет наличие решения/доказательств, но не способен оценить компетентность проверяющего или истинность источника.
- `educational`: явный ограниченный учебный допуск с предупреждением. Не полная анатомическая приёмка. Семь прежних проекционных контуров отнесены именно сюда.
- `draft` или отсутствие решения: только рабочие материалы; в атласе остаётся пин/карточка. Ни строка `status`, ни успешная проверка топологии не позволяют включить такую область.

## Поддерживаемые рецепты

| Рецепт | Вход | Что получается / ограничение |
|---|---|---|
| `indexed_surface` | Явный список исходных граней из хешированной аннотации | Поверхностная выборка; её граница автоматически вычисляется по рёбрам, встречающимся один раз |
| `edge_cycle` | Исходные рёбра | Связный замкнутый контур без ветвлений; проекция не равна всему ободку/стенкам |
| `edge_path` | Исходные рёбра | Связная незамкнутая линия с двумя концами; её анатомический ход требует отдельного решения |
| `named_primitive` | Точное имя примитива и явное `wholeOwner:true` | Целый именованный владелец; не позволяет объявить всю кость её отдельным отростком |

Технические границы поверхностной выборки записываются отдельно в `technical-boundaries.json`. Они **не попадают в манифест атласа**. Для полилиний, не совпадающих с исходными рёбрами, пока нет принятого формата: нужен отдельный проверяемый способ привязки.

## Последовательность

1. Выбрать область и сохранить точные декодированные массивы опубликованного GLB. Для головы: `tools/export-skull-region-source.mjs <run> <bone...>`. Для неизменённых ресурсов можно ссылаться на прежние снимки с проверяемыми SHA. Один снимок содержит файл, SHA декодированных байтов, bone/mesh, local/world positions, indices, matrix, geometryHash и материалы.
2. Задать рецепт. Не добавлять решение о допуске до осмотра геометрии и доказательств границ. Существующий каталог проверить через `tools/export-region-catalogue.mjs`.
3. Создать новый каталог через `createEvidenceRun` из `tools/evidence-run.mjs`. Во всех командах ниже `<run>` — его путь относительно проекта.

```powershell
node tools/export-region-catalogue.mjs <run>/catalogue.json
.venv/Scripts/python.exe -X utf8 scripts/make_skull_region_masks.py <run>
.venv/Scripts/python.exe -X utf8 tools/prepare-region-mask-review.py <run>
```

Первый вызов сборщика не публикует результат. Он сохраняет снимки рецептов/решений, `mask-candidates.json`, метрики и технические границы. Повторная запись старых доказательств запрещена. Подготовщик Blender сейчас настроен на проверочную группу основания черепа; для иной партии нужно явно задать её владельцев/ракурсы, а не использовать эти три кости по умолчанию.

4. В Blender открыть временную сцену по точным массивам; осмотреть материал выборки и техническую границу в нужных ракурсах. Сохранить изображения/метрики и восстановить пользовательскую сцену. Топология и внешний вид не заменяют источники анатомии.
5. Записать отдельное решение с автором проверки, датой, scope, причиной, хешем рецепта и путями доказательств. Если решение изменилось, создать **новый run**. Отсутствие решения безопасно оставляет draft.
6. Проверить кандидаты. Для текущей партии существуют `verify/verify_region_pipeline.py` и `tools/verify-skull-regions.mjs`. Второй проверяет опубликованный манифест, поэтому окончательная проверка обязательна после публикации.
7. Опубликовать только идентичные сохранённым, повторно проверенные результаты:

```powershell
.venv/Scripts/python.exe -X utf8 scripts/make_skull_region_masks.py <run> --publish-only
node tools/verify-skull-regions.mjs <run>
```

Публикация заменяет только генерируемый `site/skull-region-masks.json`. Кандидаты без допуска могут присутствовать в нём как отключённые определения; браузер проверяет уровень, явное решение и хеш привязки перед созданием overlay. Оригинальные модели и пины не записываются. Журнал публикации создаётся после замены файла.

8. После правки HTML пересоздать local.html; провести короткие Playwright MCP-фазы на 1280/390, сохранить каждую отдельно. Исторические JSON/PNG не заменять. Обновить постоянные VIS/GEO/PIN-задачи и журнал.

## Проверки и переносимость

Проверяются: актуальность каталога, ID/владелец, сторона в опубликованном Three.js-пространстве, диапазоны/дубликаты индексов, настоящие рёбра источника, связность, ненулевые площади, ветвления, замкнутость, хеши модели/аннотаций и точное соответствие ориентированных треугольников fallback. Допускается один или несколько вариантов ресурса, binary GLB или base64. Самопересечения неизменённых исходных костей заново не исследуются.

Fallback переносится только при точной биекции вершин и ориентированных граней. Регистрация между экземплярами/препаратами и приблизительное соответствие не поддерживаются. Несколько примитивов одного владельца требуют явного расширения экспортера/рецепта: сейчас неоднозначный владелец отклоняется. Компилятор привязывает рецепт к основному `pin.b`; дополнительные владельцы общих образований требуют отдельной проверки связей, а не обхода этого ограничения. Runtime уже умеет атомарно скрывать неполную многокостную область.

Новые области не требуют обработчика клика для каждой структуры. Для другого раздела нужно подключить его манифест к загрузчику и дать проверенные исходные снимки/рецепты; автоматическое распространение нынешних масок на другие кости недопустимо. Новая лицензия также требует соответствующей атрибуции в UI. В этой партии все аннотации происходят из BodyParts3D 3.0, DBCLS, CC BY-SA 2.1 Japan.
