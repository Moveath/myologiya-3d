# Общие ориентиры: первый рабочий пример

Это исторический отчёт первого этапа. Продолжение, исправления архитектуры и актуальный реестр: [расширение системы](shared-landmarks-expansion.md). Новые поля `catalogueBones`, `anchorStatus` и роль `component` описаны там; старые ID первого этапа сохранены.

Реализация от 15.10.2026. Объём: **яремное отверстие, справа и слева**, TA98 A02.1.00.054.
Другие новые общие ориентиры и мышцы в этот этап не включены.

## Данные и совместимость

- Концепт сохраняет существующий ID `skull-whole-054` общего каталога черепа.
- Два анатомических экземпляра: `shared_jugular_foramen_right` и `shared_jugular_foramen_left`.
- У каждого одна запись в `ATLAS.pins`, независимо от количества связанных костей.
- `relations` содержит `{bone, role, refs}`. Для этого примера роль — `boundaryContribution`:
  соответствующая височная кость и затылочная кость образуют границы отверстия.
- `refs` в отношении содержит ID проверяемых источников из `pin.refs`, а не неподтверждённое членство из списка учебного вида.
- `b` сохраняет роль основного владельца для старой навигации; для новых записей это височная кость соответствующей стороны.
- `anchors` хранит отдельно проверенный участок края, исходный пин, модель и её SHA256. Поля `p/n/loc` — совместимое представление для существующего просмотрщика.
- `view` — направление учебной камеры, не новая анатомическая координата или нормаль поверхности.
- Обратный индекс `bone → pins` содержит ссылки на один объект. Старые `b` и `sh` поддерживаются без изменения исходных записей.
- Старое `sh` означает связь каталога/контекста; ему не присваивается автоматически роль костной границы. Это сохраняет случай `carp_os_centrale` без утверждения, что восемь костей его образуют.

Собственные перечни TA98 костей не расширены общими образованиями: у затылочной кости остались 36 собственных терминов. Новые записи находятся в отдельном разделе карточки. Старые ID яремных вырезок и их повторные TA98-коды сохранены: вырезка не переименована в отверстие.

Поиск показывает один результат на экземпляр, выбирая текущую связанную кость или основного владельца. Правая и левая стороны не объединяются. Учебная ссылка ведёт к существующей карточке `whole:A02.1.00.054`; общий каталог отражает оба новых экземпляра.

## Проверенное анатомическое утверждение

Яремное отверстие ограничено каменистой частью височной кости спереди и затылочной костью сзади:

1. [Gray / Lewis, 1918](https://resources.saylor.org/wwwresources/archived/site/wp-content/uploads/2011/07/BIO302-ch2with6c6d.pdf#page=153), страница PDF 153, раздел External Surface of the Base, абзац после описания сонного канала.
2. [Singh O, Das JM, StatPearls](https://www.ncbi.nlm.nih.gov/sites/books/NBK538507/), обновление 03.04.2023, Introduction и первый абзац Structure and Function.

Проверено 15.10.2026. Это подтверждает состав костных границ, но не точные размеры, весь контур или форму отверстия конкретного образца. Текст карточки сохранён из существующего `skull_whole_terms.py`; иллюстрации источников не копировались.

## Геометрия и её ограничения

Через Blender MCP импортирована декодированная рабочая копия `site/head-q-glb.txt` в отдельную сцену. Оригинальные модели не экспортировались и не изменялись. Учтено преобразование Three.js Y-up → Blender Z-up: `(x, y, z) → (x, -z, y)`.

Использованы существующие, отдельно размеченные точки височных яремных вырезок `head_temporal_right_A02_1_06_045` и `head_temporal_left_A02_1_06_045`. Координаты не изменялись, не усреднялись и не зеркалировались. Верхние и нижние ракурсы сохранены в `shots/shared-landmarks/`.

| Сторона | Расстояние до височной сетки в Blender | На опубликованном сжатом GLB в Three.js |
|---|---:|---:|
| Правая | 0,001113 мм | 0,001100 мм |
| Левая | 0,002544 мм | 0,002588 мм |

Это численная близость к треугольникам, **не анатомическая точность с микрометровой гарантией**. До затылочной сетки около 6,5 мм: это расстояние к другой кости через область отверстия, а не ошибка точки на височной кости.

Верхний задний ракурс показывает точки на височном крае рядом с отверстием. Нижний ракурс может скрывать этот участок края. Маркер поэтому явно обозначен как проекция одного участка, а не центр просвета, весь контур или модель канала. Полная форма и размеры не объявлены подтверждёнными. Независимая приёмка анатомом не выполнялась.

Курируемое заключение и хеш: [shared-landmarks-geometry.json](shared-landmarks-geometry.json). Повторяемые измерения: [shared-landmark-blender-report.json](../verify/shared-landmark-blender-report.json).

## Поведение интерфейса

- Оба отверстия доступны в затылочной кости; соответствующее отверстие — в каждой височной.
- Выбор из любой связанной кости активирует тот же ID, текст и координату.
- Переход кнопкой или кликом по другой связанной кости сохраняет выбранный ориентир.
- При изоляции общего ориентира остаются обе участвующие кости; переход между ними сохраняет изоляцию пары.
- Просвечивание работает для обеих связанных костей. Старое состояние `xrayBone` сохраняет совместимость с прежними проверками.
- Срез скрывает отсечённый маркер; правила raycasting/BVH и индексы геометрии не менялись.
- Для записи без `p/n` остаётся доступной карточка, но не создаётся фиктивный маркер.

## Как воспроизвести

После изменения источника отношений или заключения по геометрии:

```text
python scripts/make_shared_landmarks.py
python scripts/make_skull_whole.py
python scripts/make_local.py site/index.html site/local.html
node tools/verify-shared-landmarks.mjs
```

Первая команда проверяет хеш модели и совпадение координат исходных пинов перед переносом проверенного якоря. Ручная правка `site/pins-shared.js` не требуется.

Для измерения через Blender MCP выполнить содержимое `scripts/review_shared_landmarks_blender.py` с `__file__`, установленным в путь этого скрипта. Он создаёт отдельную сцену, возвращает прежнюю активную сцену и пишет только отчёт измерений; сам не повышает статус анатомического доказательства.

`tools/verify-shared-landmarks.mjs` экспортирует `checkBrowser(page, options)` и `mcpScript(options)`. Команда `node tools/verify-shared-landmarks.mjs --mcp 390 dark` выдаёт функцию для `browser_run_code_unsafe`; локальный сервер по умолчанию — `127.0.0.1:8782`. Данные проверяются отдельно, UI — через реальный Playwright MCP. Снимки сохраняются в заранее существующую папку `shots/shared-landmarks/`.

## Результаты проверок

- Playwright MCP: 1280/390 px × светлая/тёмная темы, выбор из всех владельцев, кнопки связей, клик по маркеру и реальной сетке, изоляция пары, прозрачность, срез, уникальность поиска, отсутствие фиктивной точки и снятие выбора. Все четыре сценария прошли без ошибок консоли; [отчёт](../verify/ui-shared-landmarks-report.json).
- Штатные `verify-atlas.mjs`, `verify-navigation.mjs`, `verify-atlas-performance.mjs` прошли; проверка BVH включает совпадение лучей/faceIndex и неизменность буферов геометрии.
- Штатный `verify-mobile-layout.mjs` прошёл на 360/390/1280 px в обеих темах. Это эмуляция размеров, не физический телефон или GPU-бенчмарк.
- `verify_head.py`: 22 кости, 43 моделируемых мышечных экземпляра, прежние 521 пин сохранены.
- `verify_ta98.py`: 762 термина, прежние три документированных расхождения; новых расхождений не обнаружено.
- `verify_head_positions.py` не запустился: в доступных средах нет полного набора numpy + trimesh. Зависимости не устанавливались. Проверка двух используемых точек выполнена отдельно через Blender MCP и треугольники опубликованного GLB; остальные координаты не менялись.
- Context7 вернул описание `Triangle.closestPointToPoint` из `dev`. Сигнатура проверена по локальному `site/vendor/three/build/three.module.js`, где `REVISION = '170'`; обновление библиотек не выполнялось.

## Следующий шаг

Сначала независимая анатомическая оценка выбранного участка края на обеих сторонах. Следующее расширение механизма — один адресно подтверждённый ориентир, например `sinus tarsi`, с проверкой его костных связей и существующей точки. Автоматическое распространение на все 447 записей без координат исключено; мышцы в этот этап не входят.
